# ProTodo — Project Context

## Identity
- Product/project: **ProTodo**
- Git repository: **ProTodo**
- Solution: **ProTodo.sln**
- API: **ProTodo.Api**
- Tests: **ProTodo.Api.Tests**

## Purpose
ProTodo is a deliberately small Task Manager REST API for a Backend Developer take-home assignment.

The domain contains Projects and Tasks belonging to Projects.

## Objective
Demonstrate:
1. Backend API design
2. Relational data modeling
3. Input validation
4. Basic API security
5. Meaningful automated tests
6. Clean code
7. Effective AI-assisted development
8. Human review and correction of AI output

## Repository
The intended repository is named `ProTodo`.

The candidate may authorize Claude Code in the first prompt to create/publish the repository using the connected Git account. Documentation defines the canonical name; actual repository creation remains an explicitly authorized action.

Never store passwords, access tokens, or credential-bearing URLs in project files.

Testing:

## Scope Philosophy
Build fewer things, but make required things correct, tested, secure at the required level, and easy to review.

The assignment itself does not mandate the `ProTodo` name or this exact technology stack; these are implementation decisions for this submission.
